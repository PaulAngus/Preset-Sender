Preset Sender portable test pilot

This folder contains prebuilt, self-contained applications and tests. No .NET installation, SDK, PowerShell, Git, package restore or internet connection is required on the test machines. The private runtime files are application components, like the self-contained Sender app; they do not install or register a system runtime.

Windows 10 and Windows 11

  1. Extract the entire ZIP to an ordinary writable local folder. Do not run from inside the ZIP.
  2. Double-click Setup-Windows.cmd. It verifies the files, checks MIDI ports and runs the functional suite. It opens an HTML report.
  3. Double-click Run-Windows.cmd for functional, native MIDI and desktop checks. Keep this desktop unlocked, close normal Sender instances, and let the test finish typing into its own windows.

On Windows 10, or Windows 11 without usable MIDI Services, install loopMIDI from its author, create one port named PresetSender-Test and leave loopMIDI running. Then run the tests again. This is the only separate driver/tool required for legacy Windows; no .NET or PowerShell is installed by the pilot. An eligible Windows 11 machine uses its existing MIDI Services.

Apple Silicon Macs: prepare once on the Mac development VM

  1. Extract the Mac ZIP on the Mac development VM.
  2. Run Prepare-on-Mac-DEV.command once. It uses macOS codesign to sign the private binaries and updates the manifest. It installs nothing. The default is ad hoc signing for these private machines; a developer identity may be supplied with PILOT_SIGNING_IDENTITY. This is not Apple notarization.
  3. Run Setup-Mac.command on the development VM to validate execution, then copy the entire prepared folder to each test Mac or native OS installation. Signing is development-machine work; test machines just run the prepared files.
  4. On each installation, double-click Setup-Mac.command, then Run-Mac.command. If Finder does not launch a command file, open Terminal, type bash , drag the command file into Terminal and press Return.

For native MIDI checks, open Audio MIDI Setup → Window → Show MIDI Studio → IAC Driver, enable Device is online and add a bus named PresetSender-Test. Do this once in each macOS installation and VM. The launcher detects both PresetSender-Test and IAC Driver PresetSender-Test. Apple's instructions.

Reports

Every invocation creates a new folder under results/, including report.html, report.json, per-test results, MIDI traces, logs and screenshots. The latest path is saved in LATEST-REPORT.txt. Copy the result folder back to the development machine for investigation.

Exit codeMeaning
0All checks requested by this invocation passed.
1A check failed; inspect the report and logs.
2Required native/desktop coverage was unavailable, usually because a test MIDI port is missing.

Setup requests the functional suite. Run requests the functional/native suite on Macs and adds real desktop scenarios on Windows. Mac desktop automation, physical Fractal-device readback, installation/upgrade behaviour and notarization are outside this pilot. Missing native coverage is reported as incomplete.

Optional commands

For unattended runs, set PRESET_SENDER_NO_PAUSE=1 and pass --no-open to the launcher. Use --suite Functional, --suite Native, --suite Desktop (Windows), or --loopback "EXACT PORT NAME" when needed. No ChatGPT desktop takeover is involved.

The bundle creates test profiles and caches inside its result folders. Normal Sender settings and installed executables are not replaced. No service, scheduled task, SDK or runtime is installed. The only MIDI destinations selected are the test virtual port or a dedicated named loopback.
